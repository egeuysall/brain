# brain — canonical knowledge repo

Astro content browser + knowledge store for Ryva and personal context. Mostly Markdown/MDX and JSON; light Python/Node tooling.

## Retrieval order (cheap → expensive)
1. `context/latest/knowledge.json` — compact index and retrieval policy (~100KB; read selectively)
2. `resources/**` — manual notes, plans, articles, posts (`gym`, `saas`, `summer`, `notes`, `plans/`)
3. `context/latest/{blog,diary}/*.json` — per-entry mirrors of egeuysal.com, only when needed
4. `reports/**` — dated research (fitness validation, idea research, Reddit signals). Treat as historical evidence.

## Layout
- `agents/` — modular Ryva agent instructions, read in the order listed in AGENTS.md
- `automations/` — per-automation `memory.mdx`
- `tooling/` — `scripts/` (sync_knowledge.py, reddit_harvest.py, schedule_guard.py, ...), `tests/`, `snapshot.json`
- `resources/FORMAT.mdx` — frontmatter template for new notes

## Rules
- Never edit or refresh `tooling/snapshot.json` unless asked.
- `context/latest/**` is generated by `python3 tooling/scripts/sync_knowledge.py` — don't hand-edit.
- New manual notes: one topic per file, dated filename for time-sensitive content, frontmatter per FORMAT.mdx.
- No secrets in this repo. `.venv/` and `dist/` are not source.
- Python tests: `python3 -m unittest discover tooling/tests` (or pytest if present).
- Dev: `bun run dev` / `bun run check`.
- Don't paste large JSON dumps into context; grep or `jq` them.
