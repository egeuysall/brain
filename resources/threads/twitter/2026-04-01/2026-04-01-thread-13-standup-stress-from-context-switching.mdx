```text
In fast paced environment and lots of context switching, the thing becomes stressful for me. So I would appreciate it a cheatsheet that can help me during standup. Do you do standups? and if yes, how do you tackle it?
```

## Why It Matches Ryva ICP

This is first-person operational pain in daily standups: high switch-cost and missing ready context. It reflects small-team status rituals that consume execution time.

## Underlying Problem

Standups become stressful status theater when engineers must reconstruct project state right before speaking.

## Suggested Public Response (Copy)

```text
This is a signal the standup input quality is broken, not your process discipline. If updates require last-minute reconstruction, teams need an always-on state trail (decision, owner, next step) before the meeting starts.
```

## Suggested DM Idea (Copy)

```text
Before standup, what do you usually open first to rebuild context: Slack threads, Jira, GitHub, or all three?
```
